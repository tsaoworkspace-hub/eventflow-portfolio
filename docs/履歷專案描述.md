# EventFlow 履歷與面試描述

## 104／1111 專案標題

**EventFlow 活動行事曆與通知系統｜Java Spring Boot × Vue 3**

## 履歷精簡版

團隊專案中獨立負責活動、行事曆與通知模組的前後端開發，使用 Spring Boot、Spring Data JPA 與 Vue 3 完成活動 CRUD、月曆／地圖檢視、會員追蹤提醒、通知偏好及管理儀表板；另實作 Redis Stream 非同步通知、Email 工作重試與 Google Calendar OAuth 同步。抽出個人作品集版本後補齊 H2 展示環境、虛構種子資料及 43 個 JUnit／Mockito 測試，讓專案可在不使用團隊私有資料與密鑰的情況下獨立啟動。

## 履歷條列版

- 獨立負責團隊專案中 event、calendar、notification 模組的前後端設計與實作，完成 29 個 REST API mappings 與 37 個 Vue components/views。
- 使用 Spring Data JPA 建立活動、追蹤、通知偏好、訂閱及寄送紀錄等資料流程，並實作搜尋、分頁、狀態與輸入驗證。
- 使用 Redis Stream 規劃非同步通知佇列、consumer group 與失敗重試；Redis 關閉時保留同步寄送 fallback。
- 串接 Google OAuth 2.0／Calendar API，處理 access token 更新、事件建立／更新／刪除及外部服務失敗隔離。
- 使用 Vue 3、Leaflet 與 Chart.js 製作活動列表、月曆、地圖及營運儀表板，並以 route-level code splitting 降低首屏載入量。
- 建立 43 個 JUnit 5／Mockito 測試，涵蓋 DTO 驗證、活動提醒、通知偏好、訂閱、Email dispatch 與 Google Calendar 同步。

## 面試時的 60 秒說法

「這是我們的球鞋平台團隊專案，我負責的是活動、行事曆與通知這一整條功能，前端和後端都是我完成。管理員可以建立活動和通知，會員端可以用列表、月曆或地圖查看活動並追蹤提醒；通知部分有偏好設定、站內通知、Email，以及 Redis Stream 的非同步工作。我也串接了 Google Calendar，讓會員追蹤活動後可以同步到個人行事曆。因為原始 repository 在組員帳號且為私人，我另外抽出自己負責的模組，移除其他組員功能與密鑰，改成 H2 和虛構資料，並保留 43 個單元測試，讓面試官可以直接啟動驗證。」

## 技術追問題目

### 為什麼使用 Redis Stream？

通知寄送不應阻塞主要請求。Stream 能保留訊息、使用 consumer group 分工，並讓失敗工作有可觀察、可重試的狀態；展示環境關閉 Redis 時則走同步 fallback，降低啟動門檻。

### 如何避免 Google Calendar 掛掉影響站內追蹤？

站內追蹤是主要交易，外部同步是附加功能。程式把 Google API 失敗隔離並記錄，確保外部服務暫時不可用時，會員仍能完成站內追蹤。

### 為什麼作品集使用 H2？

正式團隊專案使用 Microsoft SQL Server，但作品集的首要目標是可重現。H2 讓 reviewer 不需準備資料庫即可啟動；JPA domain 與 MSSQL driver 仍保留，正式連線可透過環境變數切換。
